# 前端对接后端接口 · 代码约束与编程规范

> 来源：用户提供的约束规范（2026-10）。本文件为前端 / 后端联调、接口调用、数据交互层面的编码约束。
> 配套参考：`../前端页面开发规范.md`（更宏观的前端页面开发规范）。

## 一、通用强制约束（必须遵守）

1. **禁止业务代码直接写原始请求**
   - ❌ 不允许在页面组件内直接写 `axios.get/fetch`
   - ✅ 统一封装请求实例（request.js），所有接口调用走封装后的函数
   - 目的：统一 baseURL、超时、请求头、拦截器、token、错误提示
2. **接口地址统一管理，禁止硬编码 URL 散落页面**
   - 所有后端接口路径集中放在 `api/xxx.js`，按模块划分（用户模块、订单模块等）
   - 页面只导入调用：`getUserInfo(data)`，url 不写在 vue/react 组件里
3. **环境区分：开发 / 测试 / 生产 baseURL 分离**
   - 通过环境变量区分 `VITE_API_BASE_URL` / `process.env`，**禁止代码写死正式域名**
   - 禁止提交生产地址到开发分支，禁止硬编码 IP 地址
4. **接口命名约定**
   - 前端函数名：动词 + 资源，如 `getList` / `addItem` / `updateItem` / `deleteItem`
   - 和后端 REST 风格对齐：GET 查、POST 新增、PUT 全量更新、PATCH 局部更新、DELETE 删除

## 二、请求封装层约束（request 拦截器规范）

1. **请求拦截器（request interceptor）**
   - 统一携带身份凭证：token 放请求头（如 `Authorization: Bearer xxx`）
   - 统一设置请求超时时间（例如 10s）
   - 统一设置 `Content-Type`：查询/JSON `application/json`、文件上传 `multipart/form-data`、表单 `application/x-www-form-urlencoded`
   - 禁止在组件中单独修改全局请求头，特殊接口单独配置 headers
2. **响应拦截器（response interceptor）**
   - 统一解析后端返回结构体（约定后端返回固定格式：`code、data、msg`）
   - 统一拦截全局错误码：401 未登录、403 无权限、500 服务异常
   - 401 统一做跳转登录 / 清除 token，**不要每个页面单独判断 401**
   - 区分：HTTP 状态码 和 业务 code（后端自定义业务码）
3. **取消请求约束**
   - 列表分页、搜索切换、弹窗关闭时，**取消上一次 pending 请求**，防止旧请求覆盖新数据
   - 使用 axios cancelToken / AbortController

## 三、入参、出参数据约束

1. **入参校验（前端预校验）**
   - 必填项、长度、格式（手机号、邮箱）在提交前校验，减少无效请求
   - 校验提示文案统一
   - 复杂表单优先使用校验库（vee-validate / yup）
2. **参数传递规范**
   - GET：参数用 `params`；POST/PUT JSON：参数用 `data` 放请求体
   - ❌ 禁止 POST 接口把参数拼在 URL 上传递敏感数据
   - 数组、对象传参：和后端约定序列化规则
3. **出参数据处理**
   - **禁止直接使用后端原始返回对象渲染页面**，建议做数据映射（适配层）
   - 必须做空值兜底：`|| ''`、`|| []`，防止 `Cannot read property`
   - 字段命名：前端内部统一驼峰；后端返回下划线时统一转换
4. **分页参数约定**
   - 统一分页字段：pageNum、pageSize，返回 total、records，全局统一

## 四、异步调用 & 异常处理约束

1. **必须使用 async/await**，尽量避免回调地狱
2. **try/catch 分层原则**
   - 全局拦截器处理通用错误（网络错误、500、401）并给出 toast 提示
   - 业务页面 try/catch 只处理业务特有错误
   - ❌ 禁止空 catch：`catch(e){}` 吃掉错误
3. **Loading 状态约束**
   - 列表、提交接口，统一控制 loading，防止重复点击多次提交
   - 提交按钮置灰，接口结束（成功 / 失败）都要关闭 loading
   - ❌ 禁止接口异常时 loading 一直处于加载状态
4. **禁止无限重试**
   - 网络失败可配置有限重试（最多 2~3 次）；业务报错不自动重试

## 五、业务页面编码约束

1. **分离接口调用和视图渲染逻辑**
   - 组件负责 UI 展示、收集表单；接口请求、数据处理抽离到 api / composables
2. **并行 / 串行请求约束**
   - 多个无依赖接口：`Promise.all`；有依赖才顺序 await
   - `Promise.allSettled` 处理部分成功场景
3. **缓存策略**
   - 基础字典、下拉选项：内存缓存
   - 敏感 / 实时数据：禁止前端缓存
4. **不要在模板内直接调用接口**
   - ❌ `{{ getInfo() }}` 模板中执行请求

## 六、安全相关约束（重点）

1. **敏感数据**
   - token、密钥不要存在 localStorage（可选 HttpOnly cookie）；禁止打印到控制台
   - 密码、身份证等明文不要通过 URL 参数传递
2. **防重复提交**：提交按钮节流 / 锁
3. **XSS 防护**：后端返回文本不要用 `innerHTML` 直接渲染；富文本做过滤
4. **请求鉴权**：不要把密钥硬编码写在前端代码

## 七、类型 / 注释规范（TS 项目强化）

1. TS 项目必须定义接口入参、返回值类型（interface / type）
2. API 函数写 JSDoc 注释：接口用途、入参、返回值、后端版本
3. 注释写明特殊约定：字段含义、状态码说明

## 八、联调 & 文档约束

1. 前后端必须使用统一接口文档（Swagger/APIFox）
2. 接口变更时先沟通字段、返回结构，前端不要自行猜测
3. 联调阶段：增加日志（仅开发环境），生产环境关闭详细请求日志

## 九、禁止清单（红线）

- ❌ 在组件内裸写 axios/fetch
- ❌ URL 硬编码分散在页面
- ❌ 吃掉异常，空 catch 不处理
- ❌ GET 传敏感参数
- ❌ 接口请求不做 loading 防重复提交
- ❌ 直接渲染后端返回 null 对象，不做空值保护
- ❌ 生产环境打印 token、密码等敏感信息到控制台
- ❌ 接口写死 IP，环境切换需要改大量代码
